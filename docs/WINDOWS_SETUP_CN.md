# Windows 安装与长路径问题

## 推荐安装方式

需要 64 位 Python 3.11 或 3.12。将项目解压到短目录，例如 **`D:\AS`** 或 **`C:\AS`**。检查 `D:\AS\INSTALL_WINDOWS.bat` 直接存在，不要再套多层压缩包名称目录。

1. 运行 `INSTALL_WINDOWS.bat`，等待显示安装成功。
2. 再运行 `RUN_WINDOWS.bat`。
3. 开发接管时运行 `SETUP_CODEX_WINDOWS.bat`；它还会安装测试工具。

首次安装依赖需要网络；安装基础软件不会下载识别模型权重。

## 已经遇到 PySide6 “No such file or directory” / long paths

已报告的失败文件是 PySide6 内的 `qrc_qmake_Qt_labs_assetdownloader_init.cpp.obj`。在原来多层目录下，它的完整路径长 265 个 UTF-16 单元；把项目根目录缩短为 `D:\AS` 后，同一文件路径缩短到 172 个单元。传统 Windows 路径限制为 260 个单元，包括末尾空字符。

**最方便的恢复方法是从原压缩包重新解压一份到短目录，再安装。** 原目录中的项目 `.studio.json`、标注结果和媒体文件继续保留。新版本可以打开原项目；不要把原目录里安装失败或已经移动过的 `.venv` 拷贝进新目录。

如果短目录中的 `.venv` 也是本次失败安装留下的，可在确认不是其他项目环境后删除该 `.venv` 文件夹，再运行 `INSTALL_WINDOWS.bat`。不需要删除自己的项目、CSV、视频、BVH 或音频。

日志前面的 `pip-24.0.dist-info ... invalid metadata entry 'name'` 是另一条 pip 元数据警告。本次中断发生在写入过长的 PySide6 路径时；重复运行相同深目录中的安装不能缩短这条路径。

## 0.5.2 安装器的处理

安装器会在创建环境和下载依赖前检查上述已知 PySide6 文件路径。如果目录过深且系统未开启长路径支持，安装会提前停止并提示短目录方案。它保留已有环境，不会自动删除 `.venv`，也不会修改注册表或请求管理员权限。

如果系统已经开启长路径，安装器允许继续；该设置仍依赖应用自身支持，未来依赖也可能包含更长路径。短目录仍是最直接的安装方式。本次检查针对已报告的依赖文件，并非对所有未来包路径的保证。

若需要在系统层面开启长路径，可参照 [Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)。这不是安装本软件的必要步骤；设置变更可能需要管理员权限和重启，软件不会代为执行。
